# プロジェクト定義

## 背景

複数の AI を開発に活用すると、会話ごとに前提や判断が失われたり、AI ごとに作業品質や進め方がばらついたりします。

本プロジェクトは、こうした課題を解決するために、人間と AI が GitHub 上の共通ドキュメントを参照しながら協働するための枠組みを整備します。

## 目的

人間、Codex、Claude Code、ChatGPT などが、共通の目的・ルール・記録にもとづいて、安全かつ継続的に開発できる状態をつくります。

## 対象範囲

このフレームワークで扱うものは、次のとおりです。

- AI 協働のための共通ルールと役割分担
- プロジェクトの目的、要件、設計判断を記録する文書構造
- AI が作業を始める際・終える際の共通フロー
- AI 間および人間への引き継ぎ方法
- Issue、設計、レビュー、意思決定などの再利用可能なテンプレート
- Goal、MVP、Roadmap、Current State、Taskを一貫して運用するための状態遷移

## 対象外

現時点では、次のものは本プロジェクトの対象外です。

- 特定の AI サービスや IDE への依存を前提とする機能開発
- アプリケーション本体や業務システムの実装
- AI による人間の承認を不要にする完全自動の意思決定
- 組織固有の認証情報、顧客情報、機密情報の管理

## 成功とみなす状態

次の状態を達成できたとき、このフレームワークは有効に機能していると判断します。

- 新しい人間または AI が、リポジトリ内の文書だけで目的と基本ルールを把握できる
- Codex と Claude Code が、同じリポジトリで一貫した手順により作業できる
- 重要な判断について、決定内容と理由を後から確認できる
- 作業の引き継ぎ時に、変更内容・検証結果・未解決事項を把握できる
- ルールの改善を、実際の利用経験にもとづいて継続的に行える

## 主要な用語

| 用語 | 意味 |
| --- | --- |
| 人間 | 目的、優先順位、重要な判断を最終承認する参加者 |
| AI | Codex、Claude Code、ChatGPT など、開発を支援する参加者 |
| 共通ルール | すべての参加者に適用される協働上の判断基準。正本は `guidelines/AI_COLLABORATION.md` |
| 決定記録 | 重要な判断、その背景、選択肢、影響を残す文書。今後 `docs/decisions/` に格納する |
| 引き継ぎ | 次の人間または AI が作業を続けられるよう、必要な状況を記録・共有すること |
| Task Lifecycle | TaskをContext確認、Plan、承認、実装、検証、Push、完了へ進めるための状態遷移。正本は `docs/workflow/TASK_LIFECYCLE.md` |

## 現時点の未決定事項

以下は、実際の運用を通じて決定・更新します。

- ブランチ戦略とリリース方法
- テスト・品質確認の最低基準
- AI ごとに必要となる追加の操作ガイド
- 外部サービスや自動化を導入する際の承認基準

## 更新方針

この文書は、目的・範囲・成功条件に変更が生じたときに更新します。未決定事項を確定した場合は、該当するルールまたは決定記録にも反映します。

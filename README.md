# AI-Development-Framework

人間と複数の AI が、共通の前提・手順・記録にもとづいて協働開発するためのフレームワークです。

対象となる AI は ChatGPT、Claude Code、Codex などを想定しています。特定のツールに依存せず、プロジェクトの目的と判断の背景を共有しながら、継続的に開発できる状態を目指します。

## プロジェクトの目的

AI を単なるコード生成ツールとして扱うのではなく、開発チームの一員として安全かつ再現性高く活用できる共通基盤を整備します。

- 人間と AI の役割・責任範囲を明確にする
- 要件、設計判断、実装状況を AI 間でも引き継げるようにする
- 複数の AI を使っても、品質・命名・進め方の一貫性を保つ
- 新しい参加者や AI が短時間でプロジェクトを理解できるようにする

## 思想

- **人間が目的と最終判断を担う**：AI は提案・調査・実装・レビューを支援し、人間が承認します。
- **ルールはファイルとして残す**：会話だけに依存せず、判断基準と背景をリポジトリ内で共有します。
- **小さく確認しながら進める**：大きな変更を一度に行わず、目的・変更内容・検証結果を明確にします。
- **ツール非依存で設計する**：AI ごとの得意分野を活かしつつ、どの AI でも理解できる文書構造を維持します。
- **更新可能な運用にする**：ルール自体も、実際の開発で得た知見にもとづいて改善します。

## ディレクトリ構成

現時点では README のみです。今後は、次の構成を基本として整備します。

```text
.
├── README.md                 # プロジェクトの入口
├── docs/                     # 人間と AI が共有するドキュメント
│   ├── project/              # 目的、要件、用語、背景
│   ├── architecture/         # 設計方針、技術判断、構成
│   ├── workflow/             # 開発・レビュー・リリースの手順
│   └── decisions/            # 重要な意思決定の記録
├── guidelines/               # 実装・命名・テストなどの共通ルール
├── prompts/                  # AI に依頼する際の共通プロンプト
├── templates/                # Issue、設計書、レビューなどのテンプレート
└── examples/                 # フレームワークの利用例
```

## 最初に読むファイル

今はこの `README.md` が唯一の入口です。ドキュメントを追加した後は、以下の順序で読むことを推奨します。

1. `README.md` — 目的、全体像、利用方法を把握する
2. `docs/project/` — プロジェクトの背景、要件、用語を理解する
3. `guidelines/` — 実装時に守る共通ルールを確認する
4. `docs/workflow/` — タスクの進め方とレビュー方法を確認する
5. `docs/decisions/` — 既存の重要な判断と、その理由を参照する

## 開発フロー

1. **目的を共有する** — 解決したい課題、完了条件、制約を明文化します。
2. **必要な文脈を確認する** — 関連する要件、設計、既存の決定、ルールを確認します。
3. **方針を合意する** — 人間が AI の提案を確認し、実装・調査・レビューの範囲を決めます。
4. **小さな単位で変更する** — 変更の目的を限定し、影響範囲をわかる形で残します。
5. **検証する** — テスト、レビュー、仕様との照合を行い、結果を記録します。
6. **知見を還元する** — 再利用できる判断や注意点は、ルール・決定記録・テンプレートに反映します。

## 今後追加予定のドキュメント

- 複数 AI 間でコンテキストを引き継ぐためのガイド
- フレームワークの導入例と運用例

このリポジトリは、実際の開発を通じて育てていく運用フレームワークです。ルールは固定ではなく、目的に照らして継続的に改善します。

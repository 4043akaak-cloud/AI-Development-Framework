# AI-Development-Framework

人間と複数の AI が、共通の前提・手順・記録にもとづいて協働開発するためのフレームワークです。

対象となる AI は ChatGPT、Claude Code、Codex などを想定しています。特定のツールに依存せず、プロジェクトの目的と判断の背景を共有しながら、継続的に開発できる状態を目指します。

## プロジェクトの目的

AI を単なるコード生成ツールとして扱うのではなく、開発チームの一員として安全かつ再現性高く活用できる共通基盤を整備します。

- 人間と AI の役割・責任範囲を明確にする
- 要件、設計判断、実装状況を AI 間でも引き継げるようにする
- 複数の AI を使っても、品質・命名・進め方の一貫性を保つ
- 新しい参加者や AI が短時間でプロジェクトを理解できるようにする

## 思想

- **人間が目的と最終判断を担う**：AI は提案・調査・実装・レビューを支援し、人間が承認します。
- **ルールはファイルとして残す**：会話だけに依存せず、判断基準と背景をリポジトリ内で共有します。
- **小さく確認しながら進める**：大きな変更を一度に行わず、目的・変更内容・検証結果を明確にします。
- **ツール非依存で設計する**：AI ごとの得意分野を活かしつつ、どの AI でも理解できる文書構造を維持します。
- **更新可能な運用にする**：ルール自体も、実際の開発で得た知見にもとづいて改善します。

## ディレクトリ構成

現在の共通文書は、次の構成で管理します。

```text
.
├── README.md                 # プロジェクトの入口
├── docs/                     # 人間と AI が共有するドキュメント
│   ├── project/              # 目的、要件、用語、背景
│   ├── workflow/             # 開発・レビュー・リリースの手順
│   └── decisions/            # 重要な意思決定の記録
├── guidelines/               # 実装・命名・テストなどの共通ルール
├── templates/                # Issue、設計書、レビューなどのテンプレート
└── AGENTS.md                 # AI非依存の共通入口
```

## 最初に読むファイル

以下の順序で読むことを推奨します。

1. `AGENTS.md` — AI非依存の共通ルールを確認する
2. `README.md` と `docs/project/PROJECT.md` — 目的と全体像を把握する
3. `guidelines/AI_COLLABORATION.md` — 全参加者共通の協働ルールを確認する
4. `docs/decisions/ADR-001-knowledge-and-multi-ai-governance.md` — 正本と権限境界を確認する
5. `docs/workflow/AI_DELEGATION_CHARTER.md` — Context、Plan、Approval、実装、検証の順序を確認する
6. `docs/workflow/WORKTREE_POLICY.md` — 正本作業コピーを確認する
7. `docs/workflow/TASK_LIFECYCLE.md` と `templates/README.md` — Taskの状態遷移と必要な記録を確認する
8. 作業に関連する設計、Task、決定記録、Current Stateを確認する

## 開発フロー

1. **目的を共有する** — 解決したい課題、完了条件、制約を明文化します。
2. **必要な文脈を確認する** — 関連する要件、設計、既存の決定、ルールを確認します。
3. **方針を合意する** — 人間が AI の提案を確認し、実装・調査・レビューの範囲を決めます。
4. **小さな単位で変更する** — 変更の目的を限定し、影響範囲をわかる形で残します。
5. **検証する** — テスト、レビュー、仕様との照合を行い、結果を記録します。
6. **知見を還元する** — 再利用できる判断や注意点は、ルール・決定記録・テンプレートに反映します。

詳細な役割・委任・エスカレーションは、[AI Delegation Charter](docs/workflow/AI_DELEGATION_CHARTER.md) を参照してください。

## プロジェクトとTaskの記録

GitHubに、Goal、MVP、Roadmap、Current State、Task、Handoverを残します。新規プロジェクトは、[運用テンプレート](templates/README.md) の順序で作成してください。

個別Taskは、[Task Lifecycle](docs/workflow/TASK_LIFECYCLE.md) に従い、`Context Read → Planned → Approval → Implementation → Verification → Push → Done` の順で進めます。Obsidianは発想・調査・長い背景・学びの保管先とし、Taskには参照したノートと採用した制約を記録します。

## 今後追加予定のドキュメント

- プロジェクト憲章（目的、対象範囲、成功指標）
- 人間と AI の役割分担・承認ルール
- AI への依頼・回答の記録方法
- 要件定義、設計、実装、レビューの各テンプレート
- コーディング規約、テスト方針、セキュリティ方針
- Architecture Decision Record（ADR）の書き方
- 複数 AI 間でコンテキストを引き継ぐためのガイド
- フレームワークの導入例と運用例

このリポジトリは、実際の開発を通じて育てていく運用フレームワークです。ルールは固定ではなく、目的に照らして継続的に改善します。
